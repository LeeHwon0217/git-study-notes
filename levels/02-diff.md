# Lv.2 — 변경 추적 (diff) ✅

> "무엇이, 정확히 어떻게 바뀌었는가"를 읽는 법.
> 커밋하기 전에 이걸 확인하는 습관이 사고를 막습니다.

---

## 🎯 목표

`git diff`와 `git diff --staged`가 **서로 다른 구간**을 본다는 것을 이해한다.

## 🧭 핵심 그림

```
  작업 디렉토리              스테이지                저장소
   (내가 편집)              (add 완료)            (commit 완료)
       │                       │                      │
       └──── git diff ─────────┘                      │
       │                       └─ git diff --staged ──┘
       │                                              │
       └────────────── git diff HEAD ─────────────────┘
```

| 명령 | 비교 구간 | 답해주는 질문 |
|:--|:--|:--|
| `git diff` | 작업 디렉토리 ↔ 스테이지 | "아직 `add` 안 한 게 뭐지?" |
| `git diff --staged` | 스테이지 ↔ 저장소 | "이번에 커밋되면 뭐가 들어가지?" |
| `git diff HEAD` | 작업 디렉토리 ↔ 저장소 | "마지막 커밋 이후 전부 뭐가 바뀌었지?" |

> 🔑 **`add` 직후 `git diff`가 빈 화면인 건 정상입니다.**
> 변경이 앞 구간에서 뒤 구간으로 넘어갔을 뿐이에요. 사라진 게 아닙니다.

---

## 📖 diff 출력 읽는 법

실제 출력:

```diff
diff --git a/CLAUDE.md b/CLAUDE.md
index 894ead7..28cacd9 100644
--- a/CLAUDE.md
+++ b/CLAUDE.md
@@ -45,7 +45,7 @@

 기초 미션은 문서에 정리되어 있습니다.

-- [ ] 미션 1 — 첫 커밋 (`status` / `add` / `commit` / `log`)
+- [x] 미션 1 — 첫 커밋 (`status` / `add` / `commit` / `log`)
 - [ ] 미션 2 — 수정하고 차이 보기
```

| 줄 | 뜻 |
|:--|:--|
| `--- a/CLAUDE.md` | **a = 변경 전** (커밋에 저장된 버전) |
| `+++ b/CLAUDE.md` | **b = 변경 후** (지금 내 폴더의 버전) |
| `index 894ead7..28cacd9` | 파일 **내용 자체의 ID.** 내용이 달라져서 ID도 달라짐 |
| `@@ -45,7 +45,7 @@` | **위치 표시.** 45번째 줄부터 7줄 구간이 바뀜 |

### 🔍 맨 앞 한 글자만 보세요

```
1열
 ↓
 ␣기초 미션은 문서에 정리되어 있습니다.     ← 공백 = 안 바뀜 (문맥)
 -- [ ] 미션 1 — 첫 커밋                   ← -   = 삭제된 줄
 +- [x] 미션 1 — 첫 커밋                   ← +   = 추가된 줄
 ␣- [ ] 미션 2 — 수정하고 차이 보기          ← 공백 = 안 바뀜
```

**`--` 가 두 개로 보이는 이유:**

| | 1열 (Git이 붙인 기호) | 2열부터 (파일의 실제 내용) |
|:--|:--|:--|
| `-- [ ] 미션 1` | `-` 삭제 | `- [ ] 미션 1` ← 마크다운 목록 기호 |
| `+- [x] 미션 1` | `+` 추가 | `- [x] 미션 1` |
| `␣- [ ] 미션 2` | 공백 = 그대로 | `- [ ] 미션 2` |

👉 **첫 글자는 Git의 라벨, 둘째 글자부터가 진짜 내용.**
알아보는 요령: 안 바뀐 줄들이 `+`/`-` 줄보다 **한 칸 밀려 보이면** 그게 공백입니다.

---

## 💡 이 레벨의 핵심 깨달음

**Git은 글자 단위가 아니라 줄(line) 단위로 변화를 기록한다.**

체크박스 안의 한 글자(`[ ]` → `[x]`)만 바꿨는데도 Git은
*"줄 하나를 지우고, 줄 하나를 새로 넣었다"* 로 표시합니다.
이 성질은 Git을 쓰는 내내 계속 마주치게 됩니다. (충돌이 줄 단위로 나는 이유이기도 함)

---

## ✅ 실무 습관

```bash
git add .
git diff --staged     # ← 커밋 직전 반드시 확인!
git commit -m "..."
```

`git diff --staged`로 *"내가 지금 커밋하려는 게 정확히 이것뿐인가?"* 를 확인하세요.
실수로 **비밀번호, API 키, 디버그 코드**를 함께 커밋하는 사고를 막아줍니다.
